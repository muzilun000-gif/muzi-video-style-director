# 知识动画片：选题、参考片拆解与信息密度

用于"讲清一个有研究依据的知识点"的横屏动画片（认知、沟通、学习、思维误区等），尤其是**无配音、靠画面文字讲述**的账号。来自《一句玩笑的信号损耗》项目，复盘见 [案例](cases/xinhao-sunhao.md)。

## 1. 选题研究（先于 CONTENT.md）

选题和用户在对话里讨论，不直接替用户定。顺序：

1. **问清账号现状**：表现好/差的作品标题和播放、平台、时长区间、画幅、有无配音。
2. **查同类作品**：B 站公开搜索接口可以直接取数（先访问首页拿 cookie）：
   `https://api.bilibili.com/x/web-interface/search/type?search_type=video&keyword=…&order=click&pubtime_begin_s=…&pubtime_end_s=…`
   视频详情 `x/web-interface/view?bvid=`，粉丝数 `x/relation/stat?vmid=`。只保留知识分区（社科·法律·心理、科学科普、人文历史、校园学习）。
3. **报数据必须带**：来源链接、抓取时间、筛选条件、样本偏差说明（按播放排序看不到没跑起来的）。大号播放和粉丝绑定，另算"播放 ÷ 粉丝"作粗参考，不说成算法指标。
4. **找规律**：同一个号内部差距往往比号与号之间大 → 决定播放的是选题和切口。跑得好的标题写**场景或情绪**（"害怕成为嘉豪""毁掉你热爱的最快方式"），表现平的直接写**术语**（"确认偏误""沉没成本"）。
5. **分析用户自己的爆款**：抽出共同结构。例：三条爆款都是"日常憋屈场景 + 反直觉问题"（我懂你不懂 / 一句行吧却吵起来 / 新手赢高手）。新选题优先延续这个结构。
6. **低播原因只给假设**，并要后台数据才能确认：曝光、封面点击率、平均观看时长/完播、前 5 秒流失、流量来源。点击低 → 标题封面问题；点击正常完播低 → 内容节奏问题。
7. **测试计划**：2 条延续已验证结构 + 1 条检验新假设；和账号自己的历史平均比，不和大号比。不承诺爆款。

### 选题过关标准（用户复盘出的问题对应的检查）
| 问题 | 检查 |
|---|---|
| 主题不清 | 能用一句"观众原来以为 A，其实是 B"说出来 |
| 没深度、知识量不够 | 至少三层：经典实验 + 机制（为什么）+ 边界（何时不成立）。只有"一个结论 + 一句安慰"的不做 |
| 故事弱 | 有一个贯穿全片的具体场景，剧情每走一步就有一个实验来解释 |
| 开头不吸睛 | 前 3 秒是一个憋屈或反常的瞬间，不是概念名或背景介绍 |
| 讨论度 | 场景让观众自然站队（"这是嘲讽" vs "开不起玩笑"），但避开性别对立和上下级权力这类会把讨论带偏的设定 |

### 研究依据的硬规则
- **数字回到原文核对**。找原文 PDF（作者主页、机构站点），用 macOS PDFKit 抽文本：`swift -e` 不可用时写一个 3 行的 `pdf.swift`（`import PDFKit; print(PDFDocument(url:)!.string!)`）。
- 网上流传的数字在原文正文找不到就不用（例：邮件讽刺研究被广泛引用的"78% vs 56%"在原文正文中没有）。
- 原文只有图、没有数值时，画面画相对关系并标"示意"。
- 回避重复实验失败或争议大的研究（达克效应原始结论、自我损耗、权力姿势）；探索性小样本研究只能说"有研究提示，证据还弱"。
- 片中留一句边界：被试是谁、什么媒介、研究没回答什么。

## 2. 拆解参考片

用户给爆款参考时：

```bash
ffprobe -v error -show_entries format=duration:stream=codec_type,width,height,r_frame_rate -of compact ref.mp4
ffmpeg -v error -i ref.mp4 -vf "fps=1/2,scale=640:-1,tile=3x4:padding=6:color=red" sheet_%02d.jpg   # 每 2 秒一帧拼图
ffmpeg -nostats -i ref.mp4 -af "silencedetect=n=-40dB:d=0.4" -f null - 2>&1 | grep -c silence_start  # 0 ≈ 连续旁白/配乐
```

逐张看图，写 `REFERENCE.md`：结构表（时间 / 段落 / 知识单元 / 画面手法）+ 可迁移的方法 + 不照搬的东西。听不到音频要说明，只能从"底部独立字幕 + 连续音轨"推断有旁白。

《缘分的数学题》（2:03，4K）拆出的通用方法：
1. **一个母题贯穿全片**（你/TA 两个光点 + 红色"1"），每个新概念都回到它。
2. **软话题 × 硬学科**：情感话题用公式、分布、图表讲。
3. **概念版式统一**：左上中文大标题 + 英文小字 + 人名年份。
4. **数字是活的**：计数器滚动、曲线实时生长、公式解码。
5. **抽象概念后紧跟具体场景**：世界线 → "2019.09.01 07:42 地铁"左右分屏平行时间线。
6. **情绪收尾**：理性铺满后，最后一句落到能转发给朋友的情绪上。

## 3. 信息密度

用户说"别人单位时间输出 50，我只有 10"时，衡量的是**知识单元 / 秒**，不是每屏字数。
- 参考爆款约每 10 秒一个知识单元；我们的成片 12 个单元 / 168 秒 ≈ 每 14 秒一个。
- 每个实验在画面上同时给三样：**场景一句话 + 数字对比 + 一句结论**。
- 镜头快切，每个镜头只讲一件事；主反转可以单独多给时间（约 2 倍）。
- 用户作品 1–4 分钟时取上半区间，用来装下足够的单元；另附 1 分钟剪法（钩子 → 最反直觉实验 → 机制 → 最实用办法 → 落点）。

## 4. 无配音横屏的文字层

- **主画面文字**讲知识（标题、数字、图表标签）；**底部叙述行**讲故事和过渡，替代旁白。叙述行每行 ≤ 18 字，停留 ≥ 2 秒，距底 80px。
- 不另加字幕轨，除非这条有口播。
- 1920×1080 安全边距：左右 96px、上下 72px；概念标题固定左上，章节编号固定右上。

## 5. 主题与母题

动手写分镜前，用一句话定**主题**（例："语气，是发不出去的"），再配三个母题：
| 母题 | 例 |
|---|---|
| 视觉母题 | 语气波形穿过「发送」键被压成灰线；结尾第一次完整传过去 |
| 数字母题 | 一枚 50% 的硬币，主反转首次出现后留在角落，结尾落定 |
| 故事线 | 两个角色在群聊里的一句话，开头、中段、结尾三次回到它 |

## 6. 知识片的 B-roll 清单

用户说"多一点 B-roll / 创意"时，每个镜头换一种表达，不要一直"标题 + 柱状图"：
- 输入框打了又删（犹豫）、时钟滚动（时间流逝）、"对方正在输入…"出现又消失
- 卡片批量翻面（实验材料：一半真心一半反话）
- 左右分屏平行时间线（同一件事两种条件）
- 硬币翻转（≈ 随机水平）、盖章 / 打勾（自信）、连线裂成虚线（关系断裂）再愈合
- 头部轮廓里的"内心画面"（波形 + 音符）对比只剩等宽字
- 五线谱旋律 vs 一串跳动的点（知识诅咒/敲桌实验）
- 粒子从关键物件上脱落（信息丢失）
- 弹幕小测：开头请观众猜，片尾揭晓（留存 + 弹幕互动）
- 氛围层：48px 细网格、移动的暖色光晕、漂浮尘点、胶片颗粒、暗角；只在"被切断"的瞬间用一次故障切片

## 7. 数据画面的诚实规则
- 虚线柱 = "以为"，实心柱 = "实际"，差距用唯一强调色的色块标出。
- **原文说没有差距的条件不画差距块**（例：念出来时预计与实际无显著差别）。
- 数字放在不会被差距块盖住的位置（柱内或柱下），出图后专门检查。
- 群聊等界面自己画，标"界面为示意"，不仿真实 App。
- 小测题目是自编示例时，片中标"示例，不是实验原句"。
