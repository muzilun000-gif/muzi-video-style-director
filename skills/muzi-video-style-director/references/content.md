# 内容讨论

画面再好，内容不成立视频也立不住。动手写分镜和代码之前，先和用户把“这条视频讲什么、怎么讲”谈清楚，写进 `CONTENT.md`，用户确认后再进入风格和制作。

## 怎么讨论

- **带着方案来问，不要空着问。** 先根据已有信息写一版草案，再请用户改；不要只抛一串“你想要什么”。
- **一轮问完，最多 5 个问题。** 只问会改变结果的事；能合理推断的写成“我的假设”，让用户一眼能改。
- **给 2–3 个内容角度，推荐一个。** 每个角度一句话说清楚它讲什么、适合谁、代价是什么。
- **用户回复后更新 `CONTENT.md`，复述一遍定稿要点**，确认后才写分镜。用户中途改主意，回到这里改，不在分镜里硬改。

## 每条视频都要回答的五件事

1. **一句话核心信息**：看完之后观众记住的那一句。说不出这一句，内容还没想清楚。
2. **观众和场景**：谁在看、在哪看（刷短视频 / 认真学习 / 产品页），看完希望他做什么或怎么想。
3. **钩子**：前 3 秒凭什么让人停下来——一个反常识、一个冲突、一个具体画面或一个问题。
4. **具体例子或证据**：至少一个具体的东西撑住观点（真实案例、数据、对比、演示）。只有抽象说法的内容，画面只能堆装饰。
5. **结尾落点**：最后留下什么——结论、反转、行动、情绪余韵。不要无声地停在最后一个知识点。

## 内容自检

讨论定稿前过一遍，有问题就提出来，不默默照做：

- 一条视频只讲一件事；想讲的超过一件，建议拆成系列。
- 时长装得下：按中文口播约每秒 4–5 字估算，文案超出就删内容，不靠加快节奏硬塞。
- 事实有来源；不确定的地方标出来，交给用户核实。
- 每一段都在推进：删掉某段后观众没损失，这段就该删。
- 例子是观众熟悉的，不需要先解释例子本身。

## 按类型的讨论重点

**知识解释片**：观众原本以为什么、实际是什么（认知落差）；用哪个例子讲机制；哪里容易讲错。常用结构：问题 → 常见误解 → 机制/证据 → 结论与边界。

**产品宣传片**：用户的真实任务和痛点；产品做了哪一件具体的事；前后对比是什么。只讲一个最强卖点，不罗列功能清单。不编造数据和效果。

**观点/作品集短片**：观点是什么、反对的是什么；用哪个瞬间最能代表。

**音乐MV**：歌在讲什么（不只是字面歌词，是情绪和关系）；用什么画面故事或隐喻来承载；主角是谁、处在什么处境；主歌、副歌、桥段、尾声的情绪如何变化，各段落画面带来什么新东西；结尾是回到开头还是留下变化。MV 讨论的是故事和隐喻，不是逐句图解歌词。

**系列视频**：系列的共同主线和每集各自的核心信息；固定的开头/结尾形式；先确认第一集，再批量推进。

## 什么时候可以跳过

- 用户已经有确认过的脚本或文案：只做内容自检，有问题提出来，没问题直接进入制作。
- 用户明确说“直接做”“不用讨论”：自己写好 `CONTENT.md`，把做出的假设写清楚，在最终报告里列出来，方便用户回头改。
- 只是修改已有成片的画面、颜色、字体：不重新讨论内容。修改涉及内容时才回到这里。
