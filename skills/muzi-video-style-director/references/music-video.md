# 彩色音乐MV与动态歌词

## 使用范围

用于代码绘制的音乐MV、歌词动效和现有MV修改。歌曲、画幅、完整时长与用户最新风格要求优先；不默认缩成15秒，不额外生成歌曲，不要求人物对嘴。用户只要提示词时止于提示词。动手前先按 [内容讨论](content.md) 谈定这首歌的故事、隐喻和段落情绪变化；内容确认后直接制作，画面由自己内部检查，不再额外增加样片审批。

## 先分开锁定三件事

1. 画面：角色形态、场景、材质、颜色、动作。手绘是笔触与造型，不自动等于黑白；用户指定彩色后，人物、建筑、天空、道具都要有完整颜色。
2. 文字：字体、大小、语义断行、位置、逐字出现与高亮。画面采用纸张材质，不代表歌词必须有纸条或拼贴框。
3. 音频：现有原曲作为连续主时间轴。歌词文字、演唱起止、音乐段落来自实际文件，不能凭记忆编词或把均分时间戳称为逐字对齐。

修改旧项目时，复用现有音频、歌词、渲染入口和可用场景；指出被最新要求替代的旧限制。保留不合格的人物绘制方式并统一换色，通常不足以修复画面。

## 参考片拆解方法

有参考片时，按时间点抽 3–5 帧，分别记录：配色、角色与动作、场景道具、歌词的出现方式。只写看得到的东西，不推测原作者用的软件、素材或模型；短样本也不能证明同样的画面密度能撑满整首歌。最后写出“本项目适配方向”：保留什么质感、换掉什么、配色由自己提出。

拆解实例见 [案例：《借口》冷暖双人构图](cases/jiekou-cold-warm.md)。

像素风叙事MV的完整流程、角色一致性、场景装饰和氛围层见 [像素MV管线](pixel-mv.md)，用户逐轮反馈与修改复盘见 [案例：《哑键》](cases/yajian-pixel.md)。

## 歌词层执行规范

- 建立 `lyrics.json`（格式见下文），写完运行 `node scripts/validate_lyrics.mjs lyrics.json`。逐字时间不可靠时 `status` 填“待校对”，不能伪称精确。
- 场景元数据记录歌词矩形与人脸、手部、关键道具保留区。一个句子确定布局后，按完整字符串预先测量字宽，逐字出现时不重排、不左右跳。
- 选择一个主版式、至多两个变体。例：上下两行错位为主；人物侧边留白或间奏大字为变体。同一字体家族与配色保持一致。
- 建议1080p常规字56—76px、重点词82—104px；随实际句长和手机阅读检查调整。按语义与乐句分组，不能机械等字数切半。
- 将“出现”和“变色”作为两条独立时间曲线。字在真实唱到前80—160ms轻微提前进入（淡入0.12—0.18s、位移不超过约8px），唱到时改变颜色。下个语义组进入后，前组仍保留到整句读完；句尾至少留约0.25s，服从下一句开始时间。
- 主体稳定，重点字短暂放大至1.04—1.06后回稳；不让每个字同时弹跳。长音用字形内部遮罩缓慢填色，不反复闪烁。
- 深色背景用米白正文、珊瑚/暖黄高亮；浅色背景用深蓝正文、砖红/蓝色高亮。检查笔画与实际局部背景的对比；必要时用细描边或调整文字位置，用户拒绝框体时不加纸条。
- 上一行与下一行错开约0.08—0.15画宽，基线相距约1.3—1.5倍字号。避免把歌词的上/下位置误导成两个角色分别演唱。
- 歌词是最终画面的合成层。交付SRT、存在subtitle函数、MP4含字幕轨均不能证明歌词已经在视频中可见。
- 默认配色示例（深色场景）：正文米白 `#FFF3D8`、高亮暖黄 `#F4D583`、重点珊瑚 `#EB877D`、描边深蓝 `#293761`；按项目实际场景重新选色。
- 示例渲染器见 [lyric-canvas.mjs](../assets/lyric-canvas.mjs)，预览见 [lyric-demo.html](../assets/lyric-demo.html)。它只演示确定性的逐字、填色与错行，未执行歌曲识别或真实音频对齐，不是完整MV引擎。

## lyrics.json 格式

与 [lyric-canvas.mjs](../assets/lyric-canvas.mjs) 直接对应，示例见 [lyrics.example.json](../assets/lyrics.example.json)。时间都是相对原曲开头的秒数。

```json
{
  "source": { "audio": "原曲文件名", "lyrics": "歌词出处", "timing": "manual | forced-align | uniform" },
  "status": "已校对 | 待校对",
  "cues": [{
    "id": "v1-01", "start": 12.40, "end": 16.80, "text": "整句歌词",
    "lines": [{
      "x": 0.22, "y": 0.68, "size": 76, "spacing": 6, "align": "left",
      "glyphs": [{ "char": "整", "start": 12.55, "end": 12.90, "emphasis": false }]
    }]
  }]
}
```

- `x`/`y` 是画面比例坐标（0–1），`size`/`spacing` 以 1920 宽为基准。
- `timing` 为 `uniform`（均分）时，`status` 不能是“已校对”。
- 校验脚本会检查：句子顺序和重叠、每字时间落在句内且递增、各行文字拼起来等于 `text`、坐标范围，以及疑似均分的时间。

## 画面与动作

“更多动效”先增加有结果的动作与画面事件，不先增加镜头抖动或满屏粒子。可以用相邻窗户、反射、影子、两只杯子表示关系；不要照搬参考片的场景与剧情。各音乐段落带来新的信息、构图或动作，不能同一场景循环撑满原曲。

近景角色先有明确手绘轮廓与面部结构；自然动作包含预备、主要动作、接触、缓冲与跟随。接地脚锁定，握持道具时手与物体共享接触点；头、肩、髋与衣物不同步摆动。若旧骨架人物明显僵硬，应替换其绘制或关键姿态，不以纹理掩盖。

有空间连续性的镜头保持视线、运动方向、光源和物体位置一致。特殊变形需要起点、过渡、终点，不随机切成另一种画风。主歌偏表演，副歌增加空间变化，结尾回收主视觉。

## 验收

内容确认后，以下检查内部完成，不增设用户确认关卡：
- 抽查有演唱的主歌、副歌与尾段，确认歌词烧录到实际MP4，字形正确且完整；保留有时间码的检查图。
- 检查同一歌词的入场/中段/结束，布局稳定、颜色随实际唱字变化；不能仅抽一张静帧判断同步。
- 检查走路、转身、拿取等连续动作，标明检查片段；关键帧只能验证静态外观。
- 确认每个正常场景完整彩色；单纯增加少量强调色不算满足彩色要求。
- 音频从原曲头到尾连续，时长、帧率、可解码性与结尾核实；记录无法试听或无法准确对齐的部分。
- 用 `scripts/contact_sheet.sh` 出全片镜头表：同一地点连续出现、只有主体没有道具/前景的镜头都要改。
- 有混音时跑 `scripts/audio_peak.sh`，峰值高于 −0.5 dB 就降音量重新封装。
- 色彩、文字可见性、动作、内容和导出分别报告，结构验证不称为成片质量验收。
