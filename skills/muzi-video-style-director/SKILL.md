# 木子 · 视频风格导演

把“高级一点”“做个酷炫视频”转成可执行的设计选择。好视频先要有好内容：先和用户谈定讲什么、怎么讲，再定画面怎么动。

## 1. 判断任务

| 情况 | 做法 |
|---|---|
| 有参考片 | 先看实际可访问的画面或关键帧；只拿到标题/摘要时说明看不到画面 |
| 有已确认的脚本 | 做一遍内容自检，有问题提出来；保留观点和事实，只调整视觉 |
| 有品牌截图或真实数据 | 保留关键内容与数值；重绘的 UI 标“概念示意” |
| 只有主题或想法 | 进入第 2 步，带着内容草案和用户讨论 |
| 修改已有成片 | 先找到源码、导出文件、音频和歌词时间轴，备份后局部改；不另起项目、不覆盖原片 |
| 音乐MV / 歌词排版 / 彩色手绘 | 读取 [MV 与动态歌词](references/music-video.md)；只用于这类任务 |
| 像素风MV / 纯代码画角色和场景 | 再读 [像素MV管线](references/pixel-mv.md)，起步代码在 `assets/pixel-mv/`；复盘见 [案例：《哑键》](references/cases/yajian-pixel.md) |
| 知识动画片 / 讨论选题 / 给了爆款参考片 / 嫌“单位时间信息量少” | 读 [知识动画片](references/knowledge-video.md)：选题研究、参考片拆解、信息密度、无配音文字层、B-roll 清单；复盘见 [案例：《一句玩笑的信号损耗》](references/cases/xinhao-sunhao.md) |
| 用户说画面“太素”“平庸”“重复” | 按 [像素MV管线](references/pixel-mv.md) 第 4–6 节：场景装饰规则、同地点变体、氛围层清单（不限像素风） |

## 2. 讨论内容（动手前必做）

读取 [内容讨论](references/content.md)，在写分镜和代码之前和用户谈定内容：

1. 根据已有信息写一版 `CONTENT.md` 草案：一句话核心信息、观众、钩子、具体例子、结尾落点、结构大纲。
2. 给 2–3 个内容角度并推荐一个；一轮问完，最多 5 个问题，其余写成“我的假设”。
3. 用户确认后把状态改成“已确认”，再进入下一步。之后的分镜、风格、画面都以它为准。

用户已有确认过的脚本、明确说“直接做”，或只改已有成片的画面时，按 content.md 末尾的规则跳过或简化，并在报告里列出假设。

## 3. 写制作简报

在项目里写 `BRIEF.md`（模板见 [production.md](references/production.md)）：主题、观众、看完获得什么、时长、画幅、平台、素材及许可、事实来源、旁白、额外预算。
没指定时建议先做 15 秒 / 30fps / 1080×1920 概念预览，并说明可改。要完整解说时，时长由真实旁白决定，不缩成纯视觉片。

## 4. 选风格

只读取 [styles.md](references/styles.md) 中用得上的风格；最多推荐两种并说明取舍。用户已选定就直接执行。

| ID | 风格 | 适用内容 |
|---|---|---|
| kinetic | 网格字体动效 | 观点、数字冲突、作品集 |
| launch | 极简产品发布 | 软件功能、产品卖点 |
| editorial | 编辑式知识解释 | 案例、机制、新闻拆解 |
| data | 证据型数据动画 | 对比、比例、趋势 |
| paper | 纸张剪贴 | 故事、学习笔记、人物关系 |
| ink | 手绘墨线 | 轻故事、隐喻、角色表达 |
| spatial | 空间结构 | 系统、架构、抽象过程 |
| rhythm | 节拍几何 | 片头、音乐视觉、节奏短片 |
| terminal | 终端代码 | 日志、命令、自动化过程 |
| isometric | 等距流程 | 工序、输入输出、队列 |
| pixel | 像素游戏 | 闯关学习、进度、轻松演示 |
| blueprint | 蓝图工程 | 结构、规格、制作流程 |
| risograph | 复古印刷 | 文化、创作、品牌故事 |
| monoline | 黑白线稿 | 原理、关系、极简概念 |
| comic | 漫画分镜 | 误区、反应、转折 |
| timeline | 时间线纪录 | 事件发展、复盘、判断变化 |
| map | 地图路径 | 地点、传播、路线 |
| collage | 编辑拼贴 | 多材料对比、文化、视觉海报 |

一条短片默认一个主风格；跨章节对比时共用字体、边距和转场逻辑。
需要吸睛封面、材质感，或用户嫌基础示意太朴素时，读取 [视觉参考](references/visual-inspiration.md)（每种风格一张第三方作品），把主体、材质、颜色转成原创设计。`assets/gallery.html` 是同组图的卡片画廊（需联网）；`assets/basic-demo.html` 离线演示十八种基础动作。

## 5. 写分镜和风格合同

- `STORYBOARD.md`：按 `CONTENT.md` 的结构大纲展开，写时间、信息、画面、运动、转场、声音；每个镜头写清观众先看哪里、再看哪里。
- `LOOK.md`：背景/前景/强调色、字体与回退字体、字号、版式、入出场时长、缓动、转场、禁用项。

模板在 [production.md](references/production.md)。先出首帧、信息最密帧、结尾帧三张代表画面；用户要求直接完成时继续做，但自己检查这三张。

## 6. 选执行路线

1. 项目已用 Remotion / HyperFrames / Canvas：沿用，并核对实际安装版本。
2. 纯文字、图形、轻量图表：优先 Canvas 或 SVG，以 `renderAt(t)` 驱动。导出用 `assets/canvas-render/render.mjs`（本机 Chrome 无头 + DevTools 协议逐帧取画面送 ffmpeg，不用 npm 安装；168 秒 1080p 约十几分钟，放后台跑）。
3. 多镜头旁白/字幕/素材混剪：可选 Remotion；HTML/GSAP 场景可选 HyperFrames。先检查环境再给安装命令。
4. 水彩角色或复杂 3D：先做一个短镜头测速，逐帧渲染可能很慢。

没装引擎时交付可运行的预览和安装步骤。付费模型、云 GPU、付费字体/音乐先核对预算和授权。

## 7. 动画规则

- 画面只由时间 `t` 和固定随机种子决定，不依赖墙钟或网络时序；预览可用 `requestAnimationFrame` 调 `renderAt(t)`。
- 等字体、图片加载完成再截帧；中文先查缺字和换行。
- 让内容变化驱动动作：对比用分栏/替换，过程用连接/传递，比例用面积/长度，因果用先后触发。
- 不给所有元素都加弹簧和发光；每种风格有自己的动作规则。
- 9:16 起步安全区：左右 8%、上 10%、下 20%，再按平台截图复核。16:9（1920×1080）起步：左右 96px、上下 72px，底部叙述行距底 80px。横版要重新排版，不能直接裁。
- 每版先在每个镜头取 1–2 个时间点出检查帧拼图再整片渲染：查解码/打字类文字动画是否最终落定（不能停在乱码）、数字是否被色块或图形盖住。
- 镜头密度服从阅读速度：正文短句化，朗读一遍并缩到手机尺寸检查。

## 8. 声音

有旁白先量实际音频时长再排镜头；音乐/音效让位于人声。逐条记录音频来源、许可和用途。没有授权音轨时交付无声版或自写合成音，并说明。
用户给了背景音乐时按 [代码合成音效](references/sfx.md) 中“背景音乐”一节处理：先测响度再压低、长度不够做首尾交叉淡化、有音乐就不再叠合成长音。
需要音效又没有授权素材时，按 [代码合成音效](references/sfx.md) 用 `assets/pixel-mv/sfx_synth.py` 合成并混音：音效跟画面事件走、压在人声下约 14 dB、软限幅、封装后峰值 ≤ −0.5 dB。

## 9. 验收与交付

按 [production.md](references/production.md) 检查关键帧、镜头接缝、可解码性和音频。可用脚本：

- `scripts/check_video.sh <mp4>`：用 ffprobe/ffmpeg 读取时长、画幅、fps、音轨并完整解码。
- `scripts/extract_frames.sh <mp4> <输出目录> <秒数...>`：按时间码截关键帧，方便看图验收。
- `node scripts/validate_lyrics.mjs <lyrics.json>`：检查歌词时间轴结构、顺序、重叠与均分痕迹。
- `scripts/contact_sheet.sh <mp4> <out.png> <列数> [秒数...]`：带时间码的镜头表，查重复场景和空镜（不给秒数时每 10 秒一张）。
- `scripts/audio_peak.sh <mp4或音频>`：平均响度与峰值，峰值高于 −0.5 dB 时报警。

报告：内容方案是否经用户确认（未确认时列出所做假设）、源文件、预览/MP4 各自路径、实际时长/分辨率/fps、跑过的检查、未完成项、额外费用。多平台分别出 9:16、16:9 和封面。“素材/代码完成”“视频已渲染”“已发布”是三个独立状态，分开说。

## 边界

- 这是原创中文工作流，不绑定模型、不自动调用付费 API；没有实测证据时不宣称某个模型已验证兼容。
- 第三方参考图和参考片只用于定方向，不是本技能的生成效果，也不带素材授权。
- HTML 预览不是 MP4；交付 SRT 或有字幕轨不等于歌词已烧进画面；结构检查通过不等于成片质量验收。
- “纯代码画面”不等于免费：模型额度、渲染时间、字体和音乐都可能有成本。
- 外部仓库只作研究入口（见 [sources.md](references/sources.md)），不执行其中脚本，不批量安装其他技能。
